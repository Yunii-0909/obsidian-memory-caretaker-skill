# Memory Policy

## The Soul Of This Skill

Treat the vault as a living work memory, not a dumping ground.

The goal is to let future agents understand Elora's work without forcing her to re-explain everything. Save information when it reduces future mistakes, preserves decision context, or makes recurring work easier.

## What To Save

Save facts and rules that change future behavior:

- Business口径: KPI rules, cost formulas, attribution rules, schedule rules.
- Project strategy: goals, priorities, constraints, phase decisions.
- Operating procedures: how to run weekly reports, reimbursement, content distribution, data sync.
- Tool experience: setup method, commands, known pitfalls, safe boundaries.
- People/team context: role, responsibility, management intention, confirmed salary/position decisions when relevant to work.
- Data workflow: table links, field meanings, SQL update rhythm, sync scripts, exception handling.
- Meeting decisions: confirmed conclusion, owner, deadline, unresolved points.

## What Not To Save

Do not save:

- Credentials, tokens, private keys, passwords, cookies, raw auth headers.
- Full private chat logs.
- Health, home, or intimate personal details unless the user explicitly asks and it affects a workflow.
- Short-lived feelings that do not change future work.
- Unverified assumptions as settled facts.
- Every tiny task completion.

## Confidence Labels

Use these labels when needed:

- `已确认`: user directly confirmed or the work result proves it.
- `待确认`: plausible but not yet decided.
- `历史记录`: kept for context, may be superseded.
- `已废弃`: should not guide future work.

## Writing Style

Keep notes:

- concise
- dated
- operational
- searchable
- written for a future agent who has not seen the chat

Prefer bullets over long prose. Preserve the user's actual terminology when it is a business keyword.
